# Мышь в лабиринте — обучение с подкреплением (Q-learning)

Лабораторная работа № 2, «ООП на языке Java».

Мышь ищет сыр (+Z) в лабиринте, по пути может пить воду (+x) и получать удар током (−y).
Карту она не знает. После каждого хода среда сообщает ей награду, и по этим числам мышь
заполняет Q-таблицу. Через сотни эпизодов она находит выгодный путь.

## Запуск на Mac

Нужны JDK 17 или новее и Maven:

```bash
brew install openjdk@21 maven
```

Затем в папке проекта:

```bash
mvn javafx:run          # графическое приложение
mvn test                # автоматические тесты
mvn compile exec:java   # консольная демонстрация без окна
```

JavaFX скачивается Maven'ом автоматически, в том числе для Mac на Apple Silicon.

**IntelliJ IDEA:** File → Open → выбрать папку проекта (файл `pom.xml`). Запускать класс
`mousemaze.Launcher` или задачу Maven `javafx:run`.

## Как пользоваться

1. **Лабиринт.** Задайте число комнат по вертикали и горизонтали, процент петель, количество
   воды и ловушек, затем нажмите «Сгенерировать (DFS)». При 0 % петель получается идеальный
   лабиринт: между любыми клетками ровно один путь. Петли создают альтернативные маршруты.
2. **Своя схема.** Включите «Режим редактирования», выберите кисть и рисуйте мышью
   (ЛКМ ставит выбранное, ПКМ делает проходом). Схему можно сохранить в файл и загрузить.
3. **Награды и параметры** α, γ, ε задаются в левой панели.
4. **«Обучить мышь».** Справа появятся результат, график суммы выигрыша и просмотр эпизодов:
   кнопки «Эпоха 1», «Эпоха 50», «Последняя», «Найденный путь (ε = 0)», ползунок и анимация.
5. **Стрелки политики** показывают лучшее действие по Q-таблице в каждой изученной клетке.
   При наведении на клетку в строке состояния видна её строка Q-таблицы.
6. **«Снимок лабиринта» / «Снимок окна»** сохраняют PNG для отчёта и презентации.

## Формат файла схемы

```
; строки с ';' — комментарии
#####
#S..#      #  стена      .  проход
#.#T#      S  старт      C  сыр
#..C#      W  вода       T  ток (ловушка)
#####
```

Примеры лежат в папке `examples/`. `world_3x3.txt` — мир 3×3 из пояснения: мышь должна
обойти ток, и тест `QLearningTest` проверяет, что Q-значения сходятся к посчитанным вручную
(70.2 в обход тока против 55.0 через ток).

## Устройство программы

| Пакет | Классы | Роль |
|---|---|---|
| `model` | `Maze`, `CellType`, `Action`, `Position` | лабиринт как сетка клеток (стена — тоже клетка, один ход = одна клетка) |
| `generator` | `MazeGenerator`, `MazeFileIO` | DFS с откатом (через стек), петли, расстановка предметов; чтение и запись схемы |
| `env` | `Environment`, `RewardConfig`, `StepResult`, `StepEvent` | среда: правила ходов и наград, номер состояния |
| `agent` | `QLearningAgent` | Q-таблица, ε-жадный выбор, уравнение Беллмана |
| `training` | `Trainer`, `TrainingConfig`, `EpisodeResult`, `Simulation` | цикл эпизодов, спад ε, история для визуализации |
| `ui` | `MainApp`, `MazeCanvas` | интерфейс JavaFX |

**Решения, которые стоит упомянуть в отчёте:**

- **Состояние = клетка + маска выпитой воды.** Вода засчитывается один раз за эпизод.
  Если бы состояние было только координатами, мышь не отличала бы пустую лужу от полной
  и бегала бы к ней туда-сюда, то есть нарушалось бы марковское свойство. Поэтому воды
  не больше 10: каждая лужа удваивает число состояний.
- **γ = 0.99.** При γ = 0.95 сыр в 40 шагах «стоит» для мыши около 13, а ток стоит −30
  сразу. Тогда мышь «боится» единственного пути через ловушку и не доходит до сыра.
- **ε падает линейно** от 1 до 0.05 за 70 % эпизодов: хаос → поиск пути → использование опыта.
- **Штраф за шаг −1** заставляет искать короткий путь.
